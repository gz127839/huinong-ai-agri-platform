# 慧农 AI · 智慧农业助农服务平台 —— 部署与 AI 说明

本文档回答两个问题：**项目怎么跑起来**，以及 **AI 识别到底怎么工作**。

---

# 第一部分：部署

## 方式一：Windows 一键启动（推荐）

1. 安装 Python 3.10 ~ 3.13（安装时勾选 *Add Python to PATH*）
2. 进入 `05_项目源码` 目录
3. **双击 `run.bat`**

自动完成：挑空闲端口（默认 5000 起）→ 启动服务 → 等页面就绪后打开浏览器。
关掉窗口即停止服务；重复双击不会多开进程（单实例保护）。

## 方式二：命令行（跨平台）

```bash
cd 05_项目源码
pip install -r requirements.txt
python app.py
# 浏览器访问 http://127.0.0.1:5000
```

**首次运行自动建库**：生成 `data/agri.db` 并写入 14 种作物、16 条基础病害条目
（启动时按模型类别自动补齐至 34 条）、14 个商品与 3 个演示账号，无需手工导入。
AI 模型文件已在 `ai_model/` 目录随包分发，无需下载。

## 环境变量

复制 `.env.example` 按需修改（所有变量均有默认值，不配置也能运行）：

| 变量 | 作用 | 默认 |
| --- | --- | --- |
| `PORT` | 服务端口（被占自动 +1） | 5000 |
| `FLASK_DEBUG` | 调试重载，正式部署设 0 | 0 |
| `SECRET_KEY` | 会话密钥，正式部署务必修改 | change-me |
| `AI_LLM_BASE_URL` / `AI_LLM_API_KEY` / `AI_LLM_MODEL` | 自备大模型接口（任一 OpenAI 兼容服务），设置后优先于云端通道 | 留空=走云服务免密钥 |
| `AI_LLM_DISABLE_CLOUD` | 设为 1 可完全关闭云端大模型，只用知识库 / 规则规划器 | 空 |

## 方式三：服务器部署

```bash
pip install waitress
waitress-serve --host=0.0.0.0 --port=5000 app:app
```

## 手机 / 局域网访问

1. 手机与电脑连**同一 WiFi**；启动后窗口会打印形如 `http://10.x.x.x:5000` 的内网地址
2. 手机浏览器打开该地址，识别页点「拍照识别」直接唤起后置摄像头

打不开时：① 管理员运行 `手机访问放行.bat` 添加防火墙放行；② 校园网 AP 隔离改用
手机热点；③ 别用 VMware 虚拟网卡地址（192.168.200.x 等）。

## 登录墙（v4.2.1 新增）

打开站点先播放**开场动画**（点画面任意处可跳过），动画结束后停在**登录 / 注册界面**：

- 未登录访问任意页面都会被拦回登录页（`/api/*` 接口返回 401 JSON，不返回登录页 HTML）
- 登录成功后自动跳回你原本要访问的页面（URL 里的 `?next=` 只认站内相对路径，防开放重定向）
- 登录页内置"演示账号"按钮，点一下自动填好账号密码，不用手打
- 已登录再访问 `/login` 直接回首页；退出登录后回到登录页
- 界面入口：登录态下导航栏、页脚正常显示；未登录时只保留品牌与登录卡片

实现见 `app.py` 的 `auth_gate`（`before_request` 钩子）与 `templates/login.html`（`auth-gate` 样式）。

# 第二部分：AI 识别怎么工作

## 一、总体链路（四层分流）

```
上传图片
  │
  ├─① 主模型（MobileNetV2 迁移学习，ai_engine.py）
  │     判定"支持作物的叶片" → 输出作物/病害/健康 + 置信度 + 热力图
  │
  ├─② 嵌入相似度 < 0.75（开放集拒识）
  │     ├─ 物种识别通道（species_engine.py）：田间实景照片训练，
  │     │   回答"这是什么作物"（覆盖知识库全部 14 种，含水稻/小麦/茶树/油菜等），
  │     │   双门控（相似度+置信度）不足时标"疑似，仅供参考"
  │     ├─ 物种通道没把握 → ImageNet 通用模型认品类（imagenet_aux.py），引导上传叶片
  │     └─ 其他 → 如实提示"暂不支持" + 给出该作物知识库资料
  │
  └─③ 模型文件缺失/引擎异常（极端情况）
        → 自动降级为本地特征引擎（vision.py），保证演示不中断
```

## 二、主模型（叶片病害诊断）

| 项 | 说明 |
| --- | --- |
| 骨干 | MobileNetV2（ImageNet 预训练），冻结主干提取 1280 维嵌入 |
| 分类头 | crop（14 作物）/ fine（38 病害细类）/ health（健康概率）三层 |
| 推理 | ONNX Runtime，纯 CPU，单张 <1 秒；TTA 五视角取平均 |
| 文件 | `ai_model/mobilenetv2-12-feat.onnx` + `heads.npz` + `ood.npz` |
| 数据 | PlantVillage 54,305 张叶片图，种子 20261024 可复现 |
| 增强 | 旋转/缩放/亮度/失焦/JPEG 压缩（模拟手机实拍退化） |

**指标**（`ai_model/benchmark.json`）：标准图 作物 99.0% / 病害 97.1% / 健康 98.5%；
田间扰动图 86.3% / 94.6% / 97.8%。

## 三、开放集拒识（关键机制）

- 38 类嵌入均值作为类中心，推理时算与最近中心的余弦相似度
- 相似度 < 0.75 → 判定范围外 → **不给病害结论**，页面明确说明原因，
  若用户选了作物则展示知识库中该作物的病害资料
- 阈值标定：验证集误拒率 0.26%（28/10858）；真实案例：茶叶鲜叶 73.8% 被正确拒识

## 四、作物物种识别通道（v4.1 新增）

- **解决什么**：叶片模型只认识叶片。用户上传田间照/果实照/整株照时，此前只能拒识或
  由 ImageNet 兜底认少量果蔬；现在由物种通道直接回答"这是什么作物"
- **数据**：GBIF/iNaturalist 研究级鉴定的田间实景照片 2 511 张、14 类，
  覆盖知识库全部作物（含病害模型未学过的水稻、小麦、黄瓜、茶树、油菜）
- **方法**：与病害模型共享 MobileNetV2 骨干（零额外推理开销），
  多元逻辑回归分类头（纯 NumPy 训练），测试集准确率 69.2%
- **门控**：类原型余弦相似度 ≥0.58 且置信度 ≥0.60 才作为正式答案，
  否则降级到 ImageNet 兜底/知识库；置信度 <75% 时页面标注"疑似，仅供参考"
- **实测**：14 张真实白底产品图：优化前 0/14（全拒识）→ 物种通道 10/14

## 五、通用视觉兜底

`imagenet_aux.py` 加载 ImageNet 原版 MobileNetV2，对物种通道没把握的图片再认一次：
22 类常见果蔬（黄瓜/苹果/柑橘/玉米/南瓜/草莓等）给出品类结果并引导上传叶片；
仍无法判断则维持拒识。多模型互补：专家管叶片病害，物种通道管"是什么作物"，通才管果实品类。

## 六、结果可解释性

- 每次病害诊断生成**遮挡敏感度热力图**（`static/img/ai/`）：模型判定依据的叶片区域可视化
- 结果页展示 Top-3 候选与置信度分布
- 拒识时显示相似度数值与阈值，"为什么拒识"可验证

## 七、大模型农技问答（默认免密钥）

- 位置：`/assistant`
- 架构：**RAG** —— 先用关键词检索 `agri.db` 中作物/病害知识条目，
  把命中的资料作为上下文连同用户问题交给大模型，要求"仅基于给定资料 + 提醒复核"
- **通道（llm_client.py 统一管理，两条）**：
  1. 默认：WorkBuddy 云服务免密钥接口，用应用自身的 publishableKey 鉴权，
     **评委/用户不需要申请任何 API Key**（需联网）
  2. 自备：设置 `AI_LLM_BASE_URL / AI_LLM_API_KEY / AI_LLM_MODEL` 后优先使用，
     任意 OpenAI 兼容服务（DeepSeek / 通义 / 智谱 / 中转）均可
- 两条都不可用（断网 / 被禁用）时自动降级为**纯知识库检索**，页面顶部如实提示
- 默认模型 `hunyuan-chat`，失败时依次兜底 `glm-5.3-flash` / `deepseek-v4-flash`
- 首字延迟约 2~12 秒，属正常；答案一律锚定本地知识库，以降低幻觉风险

## 八、农业智能体（v4.2 新增）

- 位置：`/agent`（页面）与 `POST /api/agent`（JSON 接口，body：`{"question": "...", "image_path": "..."}`）
- 与问答助手的区别：问答助手是"检索一次 → 生成一次"；智能体是
  **规划 → 调工具 → 观察结果 → 再规划** 的循环，直到能给出可执行方案
- 工具箱：`recognize_image` / `crop_profile` / `query_disease` / `search_knowledge` /
  `list_products`，全部复用平台已有能力；每步工具名、参数、返回、耗时在页面留痕
- 双模式：默认由大模型按 ReAct 文本协议自主规划（同样走免密钥云通道，无需 Key）；
  大模型不可用时**内置规则规划器自动接管**——按问题语义与识别结果编排工具顺序，
  链路与 LLM 模式一致，断网也能完整演示（页面顶部会如实标注当前模式）
- 防幻觉约束：涉及作物/病害/用药的问题，必须完成至少 2 次有效工具调用才允许收尾；
  药剂与剂量必须来自工具返回，页面同时展示每一步的思考、工具、参数、返回与耗时
- 限制：单轮最多 6 步推理；知识库没有的资料不会编造，会提示咨询当地农技站

## 九、知识库扩充

知识库数据在 `seed_data.py`（作物/病害/商品），纯文本编辑即可；
`seed_data_ai.py` 会在启动时自动核对模型类别与知识库的一致性并补齐缺失条目。
改完删除 `data/agri.db` 重启即重建。

## 十、常见问题

| 现象 | 处理 |
| --- | --- |
| 双击 `run.bat` 闪退 | 手动运行 `python launcher.py` 看报错 |
| 端口被占 | 启动器自动 +1，看窗口提示的实际端口 |
| 识别慢 | 首次推理需初始化（几秒），之后单张 <1 秒；确认用的是 CPU 版 onnxruntime |
| 上传失败 | jpg/png/webp，≤8MB |
| 想恢复初始数据 | 删除 `data/agri.db` 重启 |
| 换电脑部署 | 拷贝整个目录即可（模型、依赖清单、建库脚本全在包内） |
