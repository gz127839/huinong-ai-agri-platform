# 慧农 AI · 智慧农业助农服务平台 —— 作品介绍

> 一套同时适配电脑端与手机端的智慧农业服务平台
> 技术栈：Python Flask + SQLite + ONNX Runtime（MobileNetV2 迁移学习）+ 原生响应式前端

---

## 一、项目立意

我国农业生产的主体仍是分散经营的小农户。对他们来说，务农的难处往往不在"肯不肯下力气"，
而在三个很具体的信息缺口：

| 农户的实际困境 | 具体表现 |
| --- | --- |
| **认不出来** | 叶片出现异常斑块凭经验判断不准，等农技员下乡往往已错过最佳处置期 |
| **不会防治** | 知道是病，但不知道该打什么药、什么时候打、打完之后田间怎么管 |
| **卖不出去** | 农产品缺少展示渠道，中间环节多，好货卖不出好价 |

**本项目的做法**是把这三件事放进同一个平台，环环相扣：

```
拍照识别作物 → 辨认病害 → 拿到可执行的防治方案 → 产出达标农产品 → 上架展销 → 采购方咨询
```

认作物、治病害、卖产品，农户用一部手机就能走完。

## 三、三大核心功能

### 1. 农作物智能识别与作物科普（`/crop-recognize`）

- 电脑端上传图片，手机端点「拍照识别」直接调用后置摄像头
- MobileNetV2 模型输出作物类别与置信度，附 Top-3 候选
- 科普内容：作物介绍、适种地区与季节、生长习性、种植管理、经济价值
- 支持范围外的照片（如未收录作物、果实特写）：系统**如实拒识**并给出引导，
  果实照片由通用视觉模型兜底认出品类

### 2. 病虫害智能诊断与防治指导（`/disease-recognize`）

- 模型三层决策：先判作物 → 再判病害细类（38 类）→ 同时输出健康概率
- **四套可直接落地的防治方案**：物理防治 / 合理用药（药剂、时机、安全间隔期）/
  田间整改 / 后期预防
- 诊断附带**遮挡敏感度热力图**：把模型关注的叶片区域可视化，结果可解释、不是黑箱
- 健康判定：无明显病斑时明确告知"未见明显病斑"并给预防建议，避免"没病也开药"
- **开放集拒识**：非支持作物的照片不硬给结论，同时呈现该作物的知识库资料兜底

### 3. 轻量化农产品助农展销（`/shop`）

- 定位为**展示与咨询型交易**（不接支付），贴合助农展销撮合场景
- 商品展示、分类筛选、搜索排序、采购清单、需求单、农户上架（后台审核）、咨询留言
- 简易后台 `/admin`：审核商品、处理需求单、回复留言、查看识别记录

### 4. AI 能力实验室（`/ai-lab`）——答辩核心页

集中展示：模型结构与训练方法、评测指标、开放集拒识真实案例（修复前后对比）、
能力边界说明。评测数据、失败案例、边界全部公开，模型的深浅一眼可见。

## 四、AI 技术方案

### 4.1 模型选型理由

| 候选方案 | 是否采用 | 理由 |
| --- | --- | --- |
| 把识别交给云端大模型 API | ✗（识别不走云端） | 农村网络不可靠、按次收费、断网即失效；识别必须离线可跑 |
| 云端大模型做语言组织（问答 / 智能体） | ✓（免密钥通道） | 只负责把检索到的资料组织成通顺易懂的回答，识别与结论仍由本地模型给出；断网自动降级为知识库 / 规则规划器 |
| 大型视觉模型（ViT 等） | ✗ | 参数量大，普通电脑 CPU 推理慢，部署门槛高 |
| 手写特征规则（HSV 比例等） | ✗（仅作降级兜底） | 不是从数据里学出来的模型：准确率低、无法泛化，仅保留为模型缺失时的应急通道 |
| **MobileNetV2 迁移学习（ONNX CPU）** | ✓ | ImageNet 预训练权重迁移到农业领域，14MB 模型 CPU 毫秒级推理，全程离线 |

### 4.2 模型与训练

- **数据**：PlantVillage 公开数据集 54,305 张叶片图，覆盖 14 种作物、38 个病害/健康细类
- **划分**：训练/验证/测试 = 8:1:1（随机种子 20261024，结果可复现）
- **迁移学习**：冻结 MobileNetV2 主干提取 1280 维嵌入，在其上训练三个分类头
  （作物 14 类 / 病害细类 38 类 / 健康二分类），权重导出为纯 NumPy 文件
- **田间退化增强**：旋转 ±28°、缩放 0.72~0.95、亮度 0.68~1.32、高斯失焦、JPEG 压缩——
  专门模拟手机实拍的抖动、暗光、模糊
- **类别平衡**：样本少的病害类过采样，避免模型偏向常见类
- **推理优化**：TTA 五视角（原图+四角+中心裁剪）取平均，代价换稳定

### 4.3 开放集识别（本项目 AI 部分最大的创新点）

真实世界里农户会拍到任何东西。闭集模型遇到没学过的作物，会**强行判成最像的已知类**
（实测：小麦照片被强判成马铃薯 99.9%）。本项目的应对：

1. 取 38 类训练样本在嵌入空间的均值作为各类中心（L2 归一化）
2. 推理时计算图像嵌入与最近类中心的**余弦相似度**
3. 低于阈值 0.75 → 判定为"范围外"，**主动拒识**：不给病害结论、不推荐用药，
   而是说明原因 + 展示该作物知识库资料
4. 阈值在验证集分布上标定：误拒率仅 28/10858 = **0.26%**

### 4.4 作物物种识别通道（实景照，v4.1 新增）

叶片模型只见过实验室叶片，用户实际上传的田间照、果实照、整株照会被开放集拒识——
"知道它不是叶片，但也说不出它是什么"。为此新增**物种识别通道**：

- 数据：GBIF/iNaturalist **研究级鉴定的田间实景照片 2,511 张、14 类**，
  覆盖知识库全部作物（含叶片模型完全没学过的水稻、小麦、黄瓜、茶树、油菜）
- 与病害模型**共享同一 MobileNetV2 骨干**，5 视角均值嵌入 → 多元逻辑回归
  （纯 NumPy 训练实现，零新增依赖），田间实景测试集准确率 **69.2%**
- **双门控**（类原型余弦相似度 ≥0.58 且置信度 ≥0.60）在真实域外照片上校准，
  没把握就标"疑似，仅供参考"或转知识库，不硬给结论
- 真实白底产品图 14 张实测：优化前叶片模型 0/14（全部拒识）→ **物种通道 10/14**

### 4.5 通用视觉兜底（多模型分层）

物种通道也没把握时：

- 果实/籽粒照片 → 调用 **ImageNet 原版 MobileNetV2** 识别品类（黄瓜 99.9%、苹果 86%，
  覆盖 22 类常见果蔬），提示"病害诊断请上传叶片"
- 超出两者范围 → 引导使用知识库与问答助手

### 4.6 农业智能体（Agent：规划 → 调工具 → 观察 → 汇总，v4.2 新增）

问答助手是单向的"检索 → 生成"，智能体则有完整的**反馈回路**：

```
目标 → 规划 → 调工具 → 观察结果 → 再规划 → … → 汇总成可执行方案
              ↑______________________________|
```

- **工具箱（5 个）**：`recognize_image` 图像识别（三通道复用）、`crop_profile` 作物档案、
  `query_disease` 病害防治方案、`search_knowledge` 知识库检索、`list_products` 农资价格库存
- **典型链路**：上传稻穗照问"叶子发黄怎么办" → 先识别（水稻 66.6%）→ 据结果查水稻档案
  → 查水稻病害防治 → 输出症状/用药/田间整改/采购建议；每步的工具名、参数、返回、耗时
  全部在 `/agent` 页面如实展示
- **双模式**：默认由大模型按 ReAct 协议自主规划（走免密钥云通道，**无需申请 Key**）；
  大模型不可用时**内置规则规划器**接管——同样是"执行一步、看一步、再决定下一步"，
  断网也能完整演示闭环。涉及病害/用药的问题强制至少 2 次工具调用，药剂剂量必须来自知识库
- **多轮记忆**：会话内保留最近 3 轮问答，可追问
- 另提供 JSON 接口 `/api/agent`，便于外部系统调用与自动化演示

### 4.7 权威评测（线上同款权重）

| 测试集 | 作物识别 | 病害识别 | 健康判定 |
| --- | --- | --- | --- |
| 标准测试图（10,861 张） | 99.0% | 97.1% | 98.5% |
| 田间扰动图（3,000 张） | 86.3% | **94.6%** | 97.8% |

扰动集上 V2→V3（引入退化增强训练）提升 **+13.4 个百分点**，说明增强策略确实有效。

## 五、系统架构

```
浏览器（响应式：PC / 平板 / 手机）
        │
Flask 应用层（app.py：路由 / 会话 / 业务逻辑）
        │
   ┌────┴─────────┬──────────────┐
AI 识别引擎     LLM 问答(可选)   数据层
ai_engine.py   ai_assistant.py  db.py + SQLite
  ├ 特征提取      └ RAG 检索       8 张表
  ├ 三层分类头        + 知识库      自动建库
  ├ 开放集检测        + LLM 生成
  ├ 物种识别通道
  ├ ImageNet 兜底
  └ 热力图 / TTA
```

- 数据库 8 张表：users / crops / diseases / products / cart_items / orders / messages / history
- **登录墙**：`before_request` 统一鉴权，未登录访问任意页面拦截到登录页（`/api/*` 返回 401），
  登录后按 `next` 回跳原目标页；识别记录 / 采购清单 / 上架商品均与账号绑定
- 前端：Jinja2 + 原生 CSS/JS，1080/900/640px 三档断点，移动端直调后置摄像头
- 降级链路：真模型 → 通用视觉兜底 → 知识库资料 → 本地特征引擎，任何一环失效服务不中断

## 六、创新点

**技术创新：**

1. **开放集拒识进农产品识别**：把人脸识别领域的 OOD 检测思想引入作物病害诊断，
   从机制上杜绝"不认识的作物被硬判"——这在同类作品里极少见
2. **双模型分层决策**：叶片病害模型（专家）+ ImageNet 通用模型（通才）级联，
   各管一段、互相兜底
3. **实景物种识别双通道**：用 GBIF/iNaturalist 开放数据自建 14 类田间实景集训练
   物种识别头，与病害模型共享骨干、零额外推理开销，把"这是什么作物"的覆盖率
   从 9/14 提升到 14/14（含水稻、小麦、茶树、油菜等病害模型未学作物）
4. **面向实拍的退化增强训练**：不换模型、不加参数，仅靠训练策略让扰动集指标 +13.4pp
5. **纯 NumPy 权重 + ONNX CPU 推理**：14MB 模型、无需 GPU、无需联网，村级电脑可跑

**应用创新：**

6. **农业智能体闭环**：不止于"接个大模型聊天"，把平台全部能力（识别/档案/防治/检索/商城）
   包成标准工具，让 AI 自己规划"先看图、再查档案、再查防治、最后给采购建议"，
   每步结果可见可查——核对执行轨迹即可验证不是表演
7. **"宁可说不会"的设计原则**：拒识时不给结论反而给知识库资料——农业 AI 给错结论
   会导致错误打药，如实拒识比虚假自信更有价值
8. **识别—诊断—科普—展销四环打通**：不是单点工具，一次登录全程可用
9. **AI 能力实验室**：把评测数据、失败案例、能力边界做成页面公开给评委与用户，
   敢于展示边界是可信度的来源

## 七、社会价值与商业潜力

| 对象 | 价值 |
| --- | --- |
| 普通农户 | 降低识别与防治门槛，减少误判造成的减产与用药浪费 |
| 农技推广 | 知识库 + 四套防治方案可作为基层农技培训素材包 |
| 合作社/村集体 | 展销模块提供零成本展示渠道，撮合采购 |

**商业路径**：村级服务站/农资店 SaaS 订阅（离线部署为卖点）→ 积累实拍数据反哺模型
（扩充水稻、小麦等类目）→ 与县域农技推广部门共建。模型全程离线、无 API 成本，
单点部署成本极低，适合在农村下沉市场推广。
